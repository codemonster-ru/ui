`packages/core/src/styles/entries/<slug>.css` at the reference. The current counterpart is in
`packages/vue/src/components/<slug>/<Name>.vue` and `packages/css/src/components/<slug>.css`.

The historical root (`packages/core/src/index.ts`) exports `createAsyncWithSkeleton`, which has
been restored in `packages/vue/src/async.ts`. It also exports `VueForgeCore`, `createVueForgeCore`,
`VfThemeProvider`, `useTheme`, preset helpers, primitive/semantic token types, `useClickOutside`,
`useDisclosure`, `useEscapeKey`, `useFloating`, `useFocusTrap`, `useId`, `useTableOfContents`,
`useBreakpoint`, `useBreakpoints`, `useBreakpointValue` and `useScrollLock`. The current split
keeps pure rules in `ui-runtime/core` and shared themes in `ui-tokens`. The opt-in Vue entry
restores the historical composables in this list; `useTheme` is available from the Vue root.
The optional `VueForgeCore` plugin and `createVueForgeCore` factory provide app-scoped theme
defaults for `VfThemeProvider`. Explicit provider props win. The [migration guide](../migrate-from-vueforge.md)
maps the old names to styled `/historical/<slug>` browser imports, CSS-free Node ESM and
CommonJS, and explicit shared stylesheet and token imports for aggregate entries.

## Evidence and next executable tasks

- The opt-in `useScrollLock` hook passed DOM-free SSR, reactive target and scope cleanup tests.
  Chrome verified overlapping body and custom element locks, wheel suppression, and inline
  restoration after the last release, including the body's native 15 px scrollbar gap.
- Vue behavior for the restored composition group is in
  `packages/vue/src/components/historical-compositions.test.ts`. Existing package suites for
  forms, navigation, data tables, overlays, layout primitives and advanced inputs cover the
  current contracts. Extend those owning suites when restoring the corresponding historical items.
- DataTable's focused Vue suite passed all 18 tests on Node 24, including scoped content,
  manual requests, sorted client pages, off-page selection, controlled expansion, mask and
  skeleton states. The navigation suite passed 10 tests after restoring routed links.
- DataTable resizing passed 20 Vue tests, 26 runtime and package checks, and seven built SSR
  checks. Chrome exposed the labelled splitter in both adapters. Keyboard, pointer and autosize
  kept the overall width at 576 px while updating the exposed splitter value. The authored
  separator passed the canonical accessibility gate.
- At a 390 px Chrome viewport, DataTable pins stayed at their logical edges in both adapters while
  unpinned columns scrolled. An 8 px keyboard resize moved the second start offset from 88 px to
  96 px, preserving the 612 px table width. The Vue source test also covered visibility changes.
- DataTable raw-row checks retained reactive records in both scopes and predicates. Chrome
  retained selection on row `501` as Vue client sort moved it, and verified the same authored
  ID and selection in Vanilla. A built Vue consumer typechecked raw and authored slot records.
- Historical DataTable pager checks covered SSR, manual clamping, controlled page and size, and
  localized summaries. Chrome at 1440 px and 390 px verified numbered jumps, compact arrows,
  retained focus on resize, and focus transfer when the previous arrow became disabled.
- Historical DataTable reorder tests covered visible previews, cancellation, and accepted column
  order including hidden keys. Chrome verified pointer and keyboard moves, restored focus, logical
  pins in LTR and RTL, and separate sorting and resize controls.
- DatePicker keyboard, locale, and form checks passed for Vue and Vanilla. A Vue production
  build passed all 22 advanced-input SSR checks, including nine DatePicker markup cases
  and disabled, readonly, and range submission. Eighteen Vue calendar tests and twelve
  runtime calendar/form tests passed. Chrome keyboard checks covered range selection,
  multiple toggling, and month and year paging with focus return in both adapters using
  light and dark themes. Chrome also verified native hour and minute changes, clamping
  to 10:30 on the following day, and Escape focus return in Vue and Vanilla. With
  a body portal, both adapters aligned the calendar to the trailing edge 2 px below the
  trigger. Arrow and Enter selected August 14 and restored trigger focus.
- Tooltip passed six Vue interaction tests and four built canonical markup cases. Chrome used the
  authored button in Vue light and Vanilla dark. Tab showed the body portal 10 px below the
  trigger and Escape hid it while retaining focus. Both triggers referenced the portal ID.
- NavMenu passed two Vue source tests and the built canonical suite. The routed fixture produced
  identical light and dark captures in both adapters. All three Chrome behavior scenarios passed
  in Vue and Vanilla. At 390 and 1280 px the production showcases skipped the disabled route in
  the Tab sequence and opened both the Core anchor and the Grid guide with Enter. Vue updated
  `aria-current` for the same-document route. The showcase link adapter resolves string and object
  paths to native anchors. A third-party router package was outside this check.
- The compact and routed NavMenu fixtures matched across adapters in light and dark. Chrome at
  390 and 1280 px verified expanded labels, icon-only controls with accessible names, Enter
  disclosure, Tab into an open branch, and the external-link glyph. Both showcase routes
  still worked. The standalone native NavMenu measured 4.10 KiB gzip without the named catalogue.
  The full native and historical namespace checks passed at 54.90 and 45.97 KiB gzip.
- New CSS subpaths are covered by the distributed package test and by the aggregate-style
  reachability check. Historical component styles use VueForge selectors and tokens. The new
  counterparts use the existing shared CodeMonster selectors and tokens. CSS class name and
